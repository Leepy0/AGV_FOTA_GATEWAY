# 경량 RTLS (태그 + 오도메트리 위치 추정) — 설계 검토

> 상태: **검토·제안 단계 (2026-10-09)**. 구현 전이며, 아래 수치와 프레임 형식은 확정이 아닙니다.
> 기준 버전: AGV_FOTA_GATEWAY v0.2.0 (2faa85b), AGV_Wifi_Bridge 983c7c0.

UWB 같은 별도 측위 장비 없이, **바닥 RFID 태그 좌표 + 모터 좌우 회전량**만으로 AGV 의 추정 위치를 맵에 표시하는 기능입니다. 이 Gateway 에 화면과 서비스로 추가해 FOTA 와 함께 쓰는 종합 웹으로 구성합니다.

## 1. 목표와 범위

| 항목 | 내용 |
|---|---|
| 용도 | 관제 표시, 정체·정지 호기 파악, OTA 전 정지 확인 |
| 용도 아님 | **교통제어 판단 근거** — 태그 사이 오차가 있어 부적합 |
| 1차 대상 | 폭 30m × 길이 150m 구간, AGV 37대 |
| 맵 입력 | 배경 이미지 + 태그 좌표만. **주행로는 그리지 않음** |

## 2. 동작 원리

1. 맵에 태그의 좌표를 찍어 둔다.
2. AGV 가 태그를 읽으면 그 태그 좌표가 현재 위치가 된다.
3. 다음 태그까지는 좌우 바퀴 회전량을 적분한 (x, y, θ) 를 태그 좌표에 얹어 표시한다.
4. 다음 태그를 읽으면 위치를 다시 맞추고, 그때 생긴 오차로 호기별 계수를 보정한다.

2D 방식은 heading(방향) 오차가 정확도를 좌우하므로 아래 네 가지가 필요합니다.

- **적분은 DSP 에서.** 서버가 1초 간격 값으로 적분하면 커브·제자리 회전에서 크게 틀어진다. DSP 가 제어 주기마다 적분하고 결과만 보낸다.
- **heading 은 연속된 두 태그로 보정.** 태그 A→B 의 실제 벡터와 추정 이동 벡터를 비교해 방향과 거리 배율을 함께 맞춘다. 태그에 방향을 따로 입력하지 않는다.
- **좌우 바퀴 편차는 호기별 자동 보정.** 좌우 지름이 0.5% 만 달라도 (트레드 500mm 가정) 10m 직진에 약 6° 틀어진다. 태그 구간마다 나오는 보정량으로 서버가 호기별 계수를 학습한다.
- **제자리 회전은 지령 각도 사용.** 슬립이 있어 엔코더 값보다 태그 명령의 회전각(90°, 180°)을 더하는 쪽이 정확하다.

### 태그 식별

바닥 태그 값은 주행 명령 코드라 유일하지 않습니다. 그래서 "추정 위치 근처에서 코드가 일치하는 가장 가까운 태그"로 식별합니다.

- 같은 코드의 태그가 가까이 붙은 곳은 헷갈릴 수 있다.
- 번호가 유일한 태그(교통제어 I/O 구역, D, B)를 **앵커**로 지정해 위치를 잃었을 때 복구 기준으로 쓴다.

## 3. 맵

### 형식

`data/maps/{id}/` 에 이미지와 `map.json` 을 둡니다 (펌웨어 저장소와 같은 방식, DB 없음).

```json
{
  "name": "1라인",
  "image": "line1.png",
  "imageSize": [3000, 600],
  "metersPerPixel": 0.05,
  "origin": [0, 0],
  "tags": [
    { "id": 17, "x": 12.5, "y": 3.0, "code": "0T21", "anchor": false }
  ]
}
```

- **태그 좌표는 픽셀이 아니라 m 단위로 저장한다.** 이미지를 바꾸거나 축척을 고쳐도 태그가 깨지지 않는다.
- 이미지는 사진이 아닌 도면이어야 한다. 원근 왜곡이 있으면 축척 하나로 보정되지 않는다.

### 업로드와 축척

PNG·JPG 를 올리면 픽셀 크기는 자동으로 읽습니다. 축척은 **두 점을 찍고 실측 거리를 입력**하는 방식을 기본으로 합니다.

| 입력 방식 | 판단 |
|---|---|
| 두 점 + 실측 거리 | **기본.** 여백·테두리와 무관 |
| 전체 실측 크기 | 이미지 테두리가 실제 경계와 일치할 때만 정확 |
| 축척 (1:100) | 이미지에 DPI 정보가 없으면 의미 없음 — 제외 |

- 두 점은 최대한 멀리 찍도록 유도한다. 클릭 오차 2px 이 100px 구간에서는 2%, 2000px 구간에서는 0.1% 다.
- 가로·세로로 한 번씩 입력받아 두 값이 1% 넘게 다르면 경고한다 (비율이 틀어진 이미지 검출).

## 4. 신뢰도 표시

| 상태 | 조건 | 표시 |
|---|---|---|
| TRACKED | 태그 2개 이상 연속 인식, 마지막 태그 이후 거리 기준 이내 | 정상 |
| DEGRADED | 마지막 태그 이후 거리 초과 / 재부팅 뒤 첫 태그만 읽음 (방향 미확정) | 오차 범위와 함께 표시 |
| LOST | heartbeat 끊김, 재부팅 감지, 라인 이탈·JOG | 마지막 위치를 회색 + 경과 시간 |

- 전원이 꺼진 사이 사람이 AGV 를 옮기면 위치를 알 수 없다. 재부팅을 감지하면 LOST 로 두고, 다음 태그에서 복구한다.
- LOST 일 때 숨기지 않고 마지막 위치를 남긴다. 멈춘 AGV 를 찾는 데 쓸모가 있다.

## 5. 지금 있는 것 / 없는 것

### 그대로 쓰는 것

| 필요 기능 | 현재 구현 |
|---|---|
| 태그 이벤트 | 브리지가 RFID 원본을 UDP 50001 로 송신, `BridgeUdpService.RfidLoop` 가 수신 (지금은 통신 로그에만 기록) |
| 앵커 | MAIN_UP 의 E 프레임 (I/O/D/B + 번호) — `MainUpForAcs` 이벤트로 흐름 |
| 전원 꺼짐 감지 | heartbeat 1초 주기 + `up`(가동 초). `up` 이 줄면 재부팅. `OfflineAfterSec`(5초) 무응답이면 오프라인 |
| 화면 갱신 | `AgvRegistry.Changed` (200ms 묶음) |
| 저장 | `data/` 폴더 + JSON |

### 새로 필요한 것

1. **오도메트리 데이터.** 브리지·Gateway 어디에도 없다. DSP 펌웨어가 새 프레임을 내보내야 한다.
2. **ACS 차단.** 새 프레임은 OTA 응답(`AgvFrame.IsOtaReply`)처럼 ACS 로 넘기지 않는다.
3. **DSP 단독 리셋 감지.** `up` 은 ESP 기준이라 DSP 만 리셋되면 잡히지 않는다. 프레임에 리셋 표시를 넣는다.

## 6. P 프레임 (제안)

브리지는 UART 를 그대로 중계하므로 수정이 없습니다. 단, ETX(0x03) 로 프레임을 자르므로 **ASCII** 여야 합니다.

태그 이벤트(ESP 경로)와 오도메트리(DSP 경로)가 따로 도착하면 순서가 어긋납니다. 그래서 DSP 가 태그를 읽는 순간 구간 마감 프레임을 보내고 적분값을 0 으로 되돌립니다.

```
<STX>P{PAN}{MSG}{AGV}M{x}{y}{θ}{상태} {BCC}<ETX>      주행 중 1초 주기 (정지 시 생략)
<STX>P{PAN}{MSG}{AGV}T{태그4}{x}{y}{θ} {BCC}<ETX>     태그 인식 시 1회
```

| 필드 | 내용 |
|---|---|
| x, y | 직전 태그 기준 이동량, mm (부호 포함) |
| θ | 직전 태그 기준 회전량, 0.1° |
| 상태 | 주행/정지, JOG, 라인 이탈, DSP 리셋 후 첫 프레임 |
| ACK | 없음 (유실돼도 다음 프레임이 누적값을 담고 있음) |

부하: 호기당 1초 1프레임으로 heartbeat(1초, 약 250B)보다 작습니다.

**미확정**: 자릿수, 상태 비트 배치, 종류 문자 `P` 가 기존 규격과 겹치지 않는지.

## 7. 작업 범위

| 저장소 | 내용 |
|---|---|
| DSP 펌웨어 | 엔코더 적분, P 프레임 송신. 가장 큰 작업 — 메인보드 리팩토링에 포함 권장 |
| AGV_Wifi_Bridge | 변경 없음 |
| `Gateway.Core` | P 프레임 파서, 위치 추정기 (순수 로직, xUnit 테스트) |
| `Gateway.Server` | 위치 서비스(HostedService), 맵 저장소, 화면 2개(맵 설정·위치 현황), ACS 필터 |
| DSP_OTA 시뮬레이터 | 가짜 주행 데이터 송신 — 하드웨어 없이 개발 |

수신·추정을 별도 프로세스로 나누지 않습니다. 브리지가 서버 IP 하나로만 통신해 UDP 수신·ACS 중계·FOTA 가 이미 한 프로세스에 있기 때문입니다.

## 8. 데이터 누적 보정

| 대상 | 방식 |
|---|---|
| 호기별 계수 (바퀴 배율, 좌우 편차) | 태그 구간마다 갱신, **자동 적용** |
| 맵 (태그 좌표) | 여러 호기의 태그 간 실측 평균과 비교해 어긋난 태그를 **제안**, 사람이 승인 |
| 주행로 | A→B 궤적을 보정해 쌓으면 평균이 주행로가 된다. 쌓인 뒤에는 위치를 궤적에 스냅해 정확도를 올린다 |

한계: 모든 호기가 맵보다 2% 길게 잰다면 맵 축척이 틀린 것인지 바퀴가 다 닳은 것인지 데이터만으로는 구분되지 않습니다. 처음 입력한 실측 거리를 기준값으로 고정하고 호기 계수를 거기에 맞춥니다.

## 9. 한계

- 태그 사이 오차는 슬립·바퀴 마모·적재에 따라 달라진다. 보정 후 태그 간격의 수 % 로 예상하나 **실측 전**이다.
- 아이콘이 주행로에서 조금 벗어났다가 태그에서 제자리로 돌아오는 모습이 보인다. 화면에서는 보간으로 부드럽게 처리한다.
- 재부팅 뒤에는 태그 하나로 위치만 잡히고, 방향은 두 번째 태그를 읽어야 확정된다.
- 호기 목록의 키가 호기 번호(01~99)뿐이다. 37대 테스트는 문제없으나, 라인 간 번호가 겹치면 맵(라인) 단위 구분이 필요하다.

## 10. 진행 순서

1. **실현성 확인.** AGV 1대로 태그 간 (x, y, θ) 를 로깅해 같은 구간 반복 주행 시 편차를 본다. 여기서 정확도 한계가 정해진다.
2. Gateway: 맵 업로드·축척·태그 배치 화면, 추정기, 위치 현황 화면 (시뮬레이터 데이터로 개발).
3. DSP 펌웨어에 P 프레임 추가, 1대 실차 검증.
4. 37대 구간 적용, 보정 데이터 수집.

## 11. 확인이 필요한 값

- 차종별 트레드(좌우 바퀴 간격), 엔코더 분해능
- 테스트 구간의 태그 간 최대 간격
- 브리지(ESP)와 메인보드가 같은 전원으로 켜지고 꺼지는지 (`up` 으로 전원 꺼짐을 판단할 수 있는지)
- RFID 리더 원본 데이터에서 태그 4byte 코드의 위치
