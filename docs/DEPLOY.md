# AGV FOTA Gateway 설치·운영 가이드

AGV 펌웨어를 무선으로 올리는 서버입니다.
사내 PC 한 대에 설치하고, 브라우저로 씁니다.
브리지(ESP32-S3)와 메인보드(TMS320F2808) 펌웨어를 올리고, 호기를 골라 순서대로 배포합니다.

- 기준 버전: Gateway **v0.3.0** · 브리지 **v0.5.1**
- 설치 파일 하나에 .NET 런타임이 들어 있습니다. PC 에 .NET 을 따로 설치하지 않습니다.
- 전체 동작 원리는 [SYSTEM_FLOW.md](SYSTEM_FLOW.md) 를 봅니다. 저장소 `docs/` 와 설치 폴더에 이 문서와 함께 들어 있습니다.

## 1. 준비물

### PC

| 항목 | 조건 |
|---|---|
| 운영체제 | Windows 10 / 11, 64비트 (x64) |
| 권한 | 관리자 권한 (서비스 등록·방화벽 규칙 때문) |
| IP | **고정 IP 권장**. 브리지마다 이 IP 를 서버 주소로 저장하기 때문 (DHCP 면 예약 주소로) |
| 네트워크 | 브리지가 붙는 Wi-Fi 망에서 이 PC 의 IP 로 닿아야 함 |
| 인터넷 | 서버 자동 업데이트를 쓸 때만. `github.com` HTTPS 443 ([9-2](#9-2-저장소-공개-여부와-사내-서버)) |
| 전원 | 항상 켜 둠. 절전 모드는 끕니다 |

### 포트

| 방향 | 포트 | 용도 | 방화벽 규칙 |
|---|---|---|---|
| 들어옴 | TCP 8080 | 웹 화면, REST API, 브리지가 펌웨어 파일을 받아 가는 주소(`/fw/`) | `install-service.bat` 이 자동 추가 (`AGV FOTA Gateway HTTP`) |
| 들어옴 | UDP 50000 | 브리지 → 서버 (heartbeat, OTA 결과, 메인보드 프레임) | 자동 추가 (`AGV FOTA Gateway Bridge UDP`) |
| 들어옴 | UDP 50001 | 브리지 RFID 로그 수신 (선택) | 위 규칙에 포함 |
| 들어옴 | TCP 6000 | ACS 중계를 `Server` 모드로 쓸 때만 | **직접 추가** |
| 나감 | TCP 443 | `github.com` — 서버 업데이트 | 보통 불필요 |
| 나감 | 설정값 | ACS 중계(`Client` 모드)·ACS REST | 보통 불필요 |

![포트와 방화벽](images/diagrams/deploy-ports.png)

*들어오는 연결 세 가지 중 TCP 8080 과 UDP 50000·50001 은 설치 스크립트가 엽니다. 서버가 브리지로 보내는 UDP 는 브리지가 보낸 주소로 되돌려 보냅니다.*

## 2. 서버 설치

### 2-1. zip 받기

GitHub 저장소 **Releases** 에서 받습니다.

| 릴리스 | 파일 이름 | 용도 |
|---|---|---|
| 정식 `vX.Y.Z` (Latest) | `AgvFotaGateway_win-x64.zip` | 운영 설치. 자동 업데이트 대상 |
| 테스트 `dev` (Pre-release) | `AgvFotaGateway-dev_win-x64.zip` | main 브랜치 시험 빌드 |

- 정식 최신판 고정 주소: `https://github.com/Leepy0/AGV_FOTA_GATEWAY/releases/latest/download/AgvFotaGateway_win-x64.zip`
- 정식 릴리스 v0.3.0 은 아직 결정 대기입니다. 그 전에는 `dev` zip 을 씁니다.
- 정식 릴리스에 함께 올라가는 `.sha256` 와 `AgvFotaGateway.json` 은 서버 자동 업데이트용입니다(`dev` 에는 `.sha256` 만). 설치할 때는 zip 만 받습니다.

### 2-2. 풀 위치

zip 안에는 `AgvFotaGateway` 폴더가 들어 있습니다.

1. zip 을 우클릭 → **속성** → 아래쪽에 **차단 해제** 가 있으면 체크하고 확인합니다.
2. zip 을 우클릭 → **모두 압축 풀기** → 대상 폴더를 `C:\` 로 지정합니다.
3. `C:\AgvFotaGateway\AgvFotaGateway.exe` 가 생겼는지 확인합니다.

> **`C:\Program Files` 아래는 피합니다.** 서비스가 `data` 폴더와 업데이트 파일을 쓰지 못할 수 있습니다. 설치 스크립트도 이 경우 경고를 띄웁니다.

폴더 안 주요 파일:

| 파일 | 내용 |
|---|---|
| `AgvFotaGateway.exe` | 서버 (런타임 포함 단일 실행 파일) |
| `appsettings.json` | 설정 ([7장](#7-설정-appsettingsjson)) |
| `start.bat` | 콘솔로 실행 (시험용) |
| `install-service.bat` | Windows 서비스로 등록 (운영용) |
| `uninstall-service.bat` | 서비스 삭제 |
| `DEPLOY.md` · `SYSTEM_FLOW.md` | 이 문서 · 전체 동작 원리 |
| `images\` | 두 문서의 그림 |

그 밖의 파일(화면용 정적 파일 등)도 그대로 둡니다. `data\` 폴더는 처음 실행할 때 생깁니다.

### 2-3. 실행 방법 고르기

| | `start.bat` (시험) | `install-service.bat` (운영) |
|---|---|---|
| 실행 | 더블클릭 | 우클릭 → **관리자 권한으로 실행** |
| 동작 | 콘솔 창에서 실행. 브라우저로 `http://localhost:8080` 을 엶 | Windows 서비스 `AgvFotaGateway` 로 등록하고 시작 |
| 끄기 | 콘솔 창을 닫으면 서버도 꺼짐 | 계속 실행. PC 를 켜면 자동 시작 |
| 죽었을 때 | 다시 실행해야 함 | 자동 재시작 |
| 방화벽 | 규칙을 만들지 않음 → 다른 PC·브리지가 못 붙을 수 있음 | TCP 8080, UDP 50000·50001 허용 규칙 추가 |
| 쓰는 곳 | 첫 확인, 오류 메시지 보기 | 현장 운영 |

> 둘을 **동시에 실행하지 않습니다.** 포트 8080 과 UDP 50000 이 겹칩니다. 서비스가 돌고 있으면 `start.bat` 을 실행하기 전에 서비스를 멈춥니다.

### 2-4. install-service.bat 이 하는 일

![install-service.bat 순서](images/diagrams/install-service-steps.png)

*관리자 권한과 exe 위치를 확인한 뒤 서비스 등록, 자동 재시작, 방화벽 규칙, 시작까지 한 번에 합니다.*

| 항목 | 값 |
|---|---|
| 서비스 이름 | `AgvFotaGateway` |
| 표시 이름 (서비스 관리자) | `AGV FOTA Gateway` |
| 시작 유형 | 자동 |
| 실패 시 | 5초 → 10초 → 30초 뒤 재시작. 실패 횟수는 하루(86400초) 지나면 초기화 |
| 방화벽 규칙 | `AGV FOTA Gateway HTTP` (TCP 8080 인바운드), `AGV FOTA Gateway Bridge UDP` (UDP 50000, 50001 인바운드) |
| 서비스 계정 | 지정하지 않음 (Windows 기본 LocalSystem) |

- 다시 실행해도 됩니다. 기존 서비스를 멈추고 지운 뒤 새로 등록합니다. `data\` 와 `appsettings.json` 은 그대로입니다.
- 끝에 `서비스 실행 중: http://localhost:8080` 이 나오고 브라우저가 열리면 성공입니다.
- `서비스 시작 실패 - 이벤트 뷰어 또는 data\logs 확인` 이 나오면 [10장](#10-문제-해결)을 봅니다.

|---|---|

## 3. 브리지 연결

### 3-1. 브리지에 서버 IP 넣기

브리지는 **설정된 서버 IP 에서 온 패킷만** 받습니다. 그래서 Gateway 는 그 IP 의 PC 에서 돌아야 합니다.

| 방법 | 언제 | 명령 |
|---|---|---|
| 휴대폰 BLE (현장 권장) | 처음 설치, 현장 | 브리지 설정 모드에서 BLE 터미널 앱으로 `AGVBR-…` 에 연결 → `login agvsetup` → `set server <PC IP>` → `save` → `reboot` |
| USB 콘솔 | 벤치 | `bridge>` 에서 `set server <PC IP>` → `save` → `reboot` |
| 서버 원격 | 이미 이 서버에 붙은 호기 | **통신 로그** 화면 → 호기 번호 입력 → **설정 명령** 칸에 `set …` → **CFG_CMD 전송** |

- 자세한 절차(앱 이름, 호기 번호·Wi-Fi·고정 IP 설정)는 브리지 저장소 [FLASH_GUIDE.md](https://github.com/Leepy0/AGV_Wifi_Bridge/blob/main/docs/FLASH_GUIDE.md) 의 "5. 호기 설정" 을 따릅니다.
- 브리지의 서버 포트(`server_port`, 기본 50000)는 Gateway 의 `Gateway.UdpPort` 와 같아야 합니다.
- 브리지 0.5.0 미만(0.3.x·0.4.x) → 0.5.x 는 파티션 표가 바뀝니다. OTA 로는 파티션 표를 못 바꾸므로 호기마다 USB 로 한 번 굽습니다. OTA 로 올리면 메인보드 열이 `⚠ 파티션 없음` 이 됩니다.

> **원격 설정은 180초 안에 확정해야 합니다.** 원격으로 저장하고 재부팅한 브리지는 `cfg` 가 `trial` 입니다. 180초 안에 서버 패킷을 받지 못하면 이전 설정으로 돌아갑니다. Gateway 는 주기적으로 패킷을 보내지 않으므로, 재부팅 뒤 **호기 현황 → 그 호기 행 → PING** 을 누릅니다. `cfg` 가 `saved` 로 바뀌면 확정된 것입니다.

> 같은 PC 에서 BridgeTest 같은 벤치 도구를 함께 띄우면 UDP 50000 이 겹칩니다.

### 3-2. 호기 현황에 나타나는지 확인

브리지가 heartbeat 를 보내면(기본 1초마다) **호기 현황** 에 한 줄이 생깁니다. 행을 누르면 상세가 열립니다.

![호기 행 상세](images/screens/02-home-detail.png)

*07호기 상세. 위 버튼으로 INFO 요청·PING 을 보내고, 그 호기의 통신 로그·배포·구역으로 바로 갑니다. 아래 검은 칸은 마지막 heartbeat 원문입니다.*

| 상세 버튼 | 하는 일 |
|---|---|
| INFO 요청 | 브리지에 상태를 바로 다시 보내라고 요청 |
| PING | 서버 패킷 1개 전송. `ota pending`·`cfg trial` 확정에 씀 |
| 통신 로그 | 이 호기로 거른 통신 로그 화면 |
| 이 호기에 배포 | 이 호기를 대상으로 채운 배포 작업 화면 |
| 구역 | 이 호기의 구역 화면 |

### 3-3. 상태 읽는 법

| 열 | 값 | 뜻 · 조치 |
|---|---|---|
| 상태 | 온라인 / `N초 전` | heartbeat 가 5초 넘게 없으면 오프라인 |
| 브리지 fw | `0.5.1` | 브리지 펌웨어 버전 |
| 슬롯 | `ota_0` / `ota_1` | 지금 실행 중인 펌웨어 칸 |
| ota | `valid` | 정상 |
| | `pending` (노란 글씨) | OTA 뒤 재부팅했지만 아직 확정 안 됨. **PING** 으로 확정. 브리지 배포 작업은 시작할 때 자동으로 확정 |
| cfg | `saved` / `default` | 저장된 설정 / 저장된 설정 없음 |
| | `trial` | 원격 설정 확정 대기. 180초 안에 **PING** |
| | `(AP)` 붙음 | 무선 설정 모드가 켜져 있음 |
| RSSI | -60 이상 | 좋음 (초록) |
| | -60 ~ -70 | 보통 |
| | -70 ~ -80 | 약함 (노랑) |
| | -80 미만 | 매우 약함 (빨강). AP 위치 확인 |
| 메인보드 앱 / 부트 | `1.0.3 / 1.0.0` | 앱 버전 / 부트로더 버전 |
| | `-` | 브리지가 0.5.0 미만이라 메인보드 OTA 미지원 |
| | `? / …` | 메인보드 앱이 버전 응답을 안 함 ([10장](#10-문제-해결)) |
| | `⚠ 파티션 없음` | 브리지에 `dspfw` 파티션이 없음. USB 전체 굽기 필요 |
| | `⟳ 프로그래밍` | 메인보드를 굽는 중 |
| 스테이징 | `1.0.3 (job …)` / `받는 중` | 브리지가 받아 둔 메인보드 이미지 |
| MAIN ↑/↓ | 숫자 | 메인보드 프레임 수 (호기→서버 / 서버→호기) |
| 손실 | 숫자 | 패킷 순번 누락 수. 늘어나면 무선 품질 확인 |

위쪽 단추로 거릅니다: 전체 · 온라인 · 오프라인 · OTA 미확정 · 메인보드 작업 중, 브리지 버전별, 메인보드 버전별, 구역, 검색(호기·IP·버전·구역).

## 4. 펌웨어 올리기

메뉴 **펌웨어** 에서 올립니다.

![펌웨어 화면](images/screens/04-firmware.png)

*메인보드 두 버전과 브리지 한 버전이 올라가 있습니다. 진행·예약 작업이 쓰는 1.0.3 은 삭제 단추가 꺼져 있습니다.*

### 4-1. 종류별 차이

| | 메인보드 (DSP) | 브리지 (ESP32-S3) |
|---|---|---|
| 종류 선택 | `메인보드 DSP (TMS320F2808, .dspfw)` | `브리지 ESP32-S3 (agv_wifi_bridge.bin)` |
| 파일 | `.dspfw` 한 개 | `agv_wifi_bridge.bin` 한 개 (앱 이미지만) |
| 만드는 법 | CCS 빌드 결과를 `tools/dsp_pack.py pack app.hex -o app_1.2.3.dspfw --ver 1.2.3` 로 묶음 | 브리지 빌드 zip `agv_wifi_bridge_<버전>.zip` 안에 있음 |
| 버전 | 파일 헤더에서 읽음. **8자 이하**, 영문·숫자·`._-` 만 (예: `1.2.3`). 9자 이상도 올라가지만 적용 뒤 '실패'로 기록됨 | 이미지 안 앱 정보에서 읽음 |
| 받는 쪽 조건 | 브리지 0.5.0 이상(`dspfw` 파티션 있음) + 메인보드에 부트로더와 재링크한 앱 | 서버에 붙은 브리지. 단 0.5.0 미만 → 0.5.x 는 USB 로 한 번 |
| 적용 중 영향 | 메인보드 앱이 약 20~30초 멈춤 | 브리지 재부팅으로 수 초 끊김 |

### 4-2. 올리는 순서

1. **종류** 를 고릅니다.
2. 파일을 고릅니다.
3. **버전** 은 비워 둡니다. 파일에서 읽습니다. 적으면 파일 버전과 같은지 확인만 합니다.
4. **메모** 에 변경 내용을 적습니다. 비우면 브리지는 빌드 정보가 들어갑니다.
5. **업로드** 를 누릅니다. 아래 목록에 한 줄이 생깁니다.

파일 크기는 64MB 까지입니다.

### 4-3. 거부되는 경우

| 메시지 | 원인 | 조치 |
|---|---|---|
| `.dspfw 형식이 아니거나 CRC 가 틀립니다` | `dsp_pack.py` 출력이 아니거나 손상 | `dsp_pack.py` 로 다시 만듦 |
| `ESP-IDF 앱 이미지가 아닙니다 … bootloader·partition-table·merged 이미지는 불가` | `merged.bin` 등 다른 파일 | zip 의 `agv_wifi_bridge.bin` 을 올림 |
| `프로젝트가 '…' 입니다 — 'agv_wifi_bridge' 빌드만` | 다른 프로젝트 빌드 | 브리지 프로젝트 빌드를 올림 |
| `입력한 버전 … 과 파일 헤더 버전 … 이 다릅니다` (브리지는 `… 과 이미지 버전 … 이 다릅니다`) | 버전 칸에 다른 값 | 버전 칸을 비움 |
| 버전 옆 ⚠ | 같은 종류·버전이 둘 이상 (거부는 아님) | 헷갈리지 않게 오래된 것을 삭제 |
| **삭제** 단추가 꺼짐 | 예약·실행 중인 작업이 이 펌웨어를 씀 | 작업을 먼저 취소 |

## 5. 구역 등록

호기를 5단계로 분류합니다: **제품군 → 층 → 라인 → 공정 → 라우트**.
구역을 등록하면 "B제품 3층 L4 전체" 처럼 한 번에 배포할 수 있습니다.

![구역 5단계 예시](images/diagrams/zone-hierarchy.png)

*아래 화면과 같은 예시입니다. 각 호기는 맨 끝 단계에 붙습니다.*

![구역 화면](images/screens/03-groups.png)

*왼쪽 트리에서 A제품 / 2F / L1 을 고른 화면. 오른쪽에 그 아래 호기 2대가 나오고, "이 호기들에 배포 →" 로 바로 작업을 만듭니다.*

> 구역 이름에 `/` 를 쓰지 않습니다. 단계 구분자와 겹쳐 다른 구역의 호기가 함께 선택될 수 있습니다([점검 G-01](REVIEW_2026-10-10.md#5-1-구역-경로-충돌-g-01--g-02--묶음-11)).

등록 방법은 세 가지입니다.

| 방법 | 쓰는 곳 | 출처 표시 |
|---|---|---|
| 직접 추가 | 한두 대 | `manual` |
| CSV 붙여넣기 | 여러 대 한 번에, 엑셀에서 복사 | `import` |
| ACS 에서 받기 | ACS 가 호기 소속을 알려 줄 때 | `acs` |

### 5-1. 직접 추가

1. **직접 추가** 칸에 호기 번호(1~99)와 각 단계 값을 적습니다.
2. **추가** 를 누릅니다.

- 아직 접속하지 않은 호기도 넣을 수 있습니다.
- 같은 호기를 다시 넣으면 덮어씁니다.
- 목록의 **수정**·**삭제** 로 고칩니다.

### 5-2. CSV 붙여넣기

**CSV 붙여넣기 (일괄)** 칸에 붙여 넣고 **가져오기** 를 누릅니다.

```csv
agv,제품군,층,라인,공정,라우트,이름
7,A제품,2F,L1,조립,자재X,AGV-07
12,A제품,2F,L1,검사,자재Y
```

- 열 순서: `agv,제품군,층,라인,공정,라우트,이름`. 이름은 생략할 수 있습니다.
- 첫 줄 머리글은 건너뜁니다. `#` 로 시작하는 줄은 주석입니다.
- 엑셀에서 열을 복사해 붙여도 됩니다(탭 구분).
- 값에 쉼표가 있으면 큰따옴표로 묶습니다.
- 호기 번호는 1~99. 틀린 줄은 결과에 `N행: …` 으로 나오고 나머지는 반영됩니다.
- **CSV 내려받기** 로 지금 목록을 같은 형식으로 받습니다.

### 5-3. ACS 에서 받기

> ACS 응답 형식은 아직 확정 전입니다(임시 형식). 지금은 직접 추가·CSV 를 씁니다.

1. `appsettings.json` 의 `AcsInventory` 섹션을 채웁니다 ([7장](#7-설정-appsettingsjson)).
2. `AcsInventory.Enabled` 를 `true` 로 바꾸고 서비스를 재시작합니다.
3. **구역** 화면 위 **응답 미리보기** 로 저장 없이 해석 결과를 봅니다.
4. 맞으면 **지금 받기** 를 누릅니다. 이후에는 `IntervalSec`(기본 300초)마다 받습니다.

- 기본값으로는 직접 넣은 값(`manual`·`import`)을 덮어쓰지 않습니다 (`OverrideManual: false`).
- ACS 목록에서 빠진 `acs` 출처 호기는 지웁니다 (`RemoveMissing: true`).
- 필드 이름 맞추기는 [ACS_API.md](https://github.com/Leepy0/AGV_FOTA_GATEWAY/blob/main/docs/ACS_API.md) 를 봅니다.

## 6. 배포 작업

### 6-1. 시작 전 안전 수칙

> **AGV 를 세운 상태에서만 실행합니다.** 서버는 정지 여부를 자동으로 확인하지 않습니다.

- 메인보드: 굽는 약 20~30초 동안 메인보드 앱이 멈춥니다. ACS 응답도 끊깁니다.
- 브리지: 재부팅으로 수 초 동안 통신이 끊깁니다.
- 서버 작업은 메인보드 이미지 받기와 적용을 이어서 합니다. 작업을 시작하기 전에 세웁니다.
- 메인보드 앱이 정지 확인 코드를 갖고 있으면 주행·충전 중일 때 거부합니다(`app_ng_01`, `app_ng_02`).
- 호기는 **한 대씩 순서대로** 진행합니다. 작업도 한 번에 하나만 실행합니다.
- **지금 시작** 은 확인창 없이 바로 시작합니다. 누르기 전에 대상 대수를 다시 봅니다. **직접 입력** 칸에 넣은 호기는 버튼의 대수에 포함되지 않습니다.
- **통신 로그** 의 수동 전송(MAIN_DOWN·CFG_CMD)은 호기 칸 기본값이 `7` 이고 확인창이 없습니다. 보내기 전에 호기 번호를 꼭 확인합니다.

### 6-2. 작업 만들기

메뉴 **배포 작업** → **새 작업**.

![새 작업](images/screens/05-jobs-new.png)

*구역으로 선택에서 B제품 / 3F / L4 를 골라 "추가 (2 대)" 를 누른 화면. 31·45호기가 선택되고 작업 이름이 자동으로 채워졌습니다.*

1. **펌웨어** 를 고릅니다. `[메인보드 DSP]` / `[브리지 ESP]` 와 버전이 보입니다.
2. **작업 이름** 은 비워도 됩니다. 비우면 `메인보드 1.0.3` 처럼 종류·버전으로 정해집니다. 구역으로 고르면 `B제품 / 3F / L4 전체` 처럼 채워집니다.
3. **대상 호기** 를 고릅니다.
   - **구역으로 선택**: 제품군 → 층 → 라인 → 공정 → 라우트 순서로 고르고 **… 추가 (N 대)** 를 누릅니다.
   - **온라인 전체 선택**: 지금 온라인인 호기 전부.
   - **업데이트 필요한 호기 선택**: 고른 펌웨어와 버전이 다른 온라인 호기만. 메인보드 OTA 를 못 받는 호기는 뺍니다. 펌웨어를 먼저 골라야 켜지고, 누르면 기존 선택을 지우고 다시 고릅니다.
   - 칩을 하나씩 눌러도 됩니다. 칩의 작은 글씨는 그 호기의 현재 버전입니다.
   - **직접 입력**: `7, 12-15` 처럼 아직 안 보이는 호기를 적습니다.
4. **실행 시각**: `지금 바로` 또는 `예약` (날짜·시각 입력).
5. **한 대라도 실패하면 나머지 중단** 은 켜 둡니다(기본).
6. **지금 시작 (N대)** 또는 **예약 (N대)** 를 누릅니다.

| 칩 모양 | 뜻 |
|---|---|
| 파란 배경 | 선택됨 |
| 초록 테두리 | 이미 이 버전 |
| 점선 | 오프라인. 실행할 때도 heartbeat 가 없으면 그 호기는 실패 |
| 빨간 테두리 | 메인보드 펌웨어를 고른 경우, 메인보드 OTA 를 받을 수 없음 (브리지 0.5.0 미만 또는 파티션 없음) |
| `미접속` | 구역에만 있고 아직 heartbeat 가 없음 |

다른 화면에서 바로 오기:

- **구역** 화면 → **이 호기들에 배포 →**: 그 구역의 호기가 채워집니다.
- **호기 현황** 상세 → **이 호기에 배포**: 그 호기가 채워집니다.

### 6-3. 진행 보기

![실행 중 작업](images/screens/06-jobs-running.png)

*31호기 메인보드를 굽는 중(40%, erase). 45호기는 대기. 메뉴에 "배포 작업 ⟳ 1" 로 실행 중임이 보입니다.*

- 실행 중인 작업은 자동으로 펼쳐집니다.
- 작업 줄에 전체 진행 막대가, 호기 줄에 호기별 진행률과 `이전 → 이후` 버전이 나옵니다.
- 진행 중·실패한 호기는 로그가 바로 보입니다. 다른 호기는 줄을 누르면 로그가 열립니다.
- 메인보드 진행률: 받기 5~30% → 스테이징 30% → 시작 32% → 진입 35% → 지우기 40% → 쓰기 45~90% → 검증 92% → 완료 100%.

### 6-4. 결과와 실패 대처

![작업 목록](images/screens/07-jobs-list.png)

*실패한 "A제품 / 2F / L2 전체" 를 펼친 화면. 23호기가 `erase_timeout` 으로 실패했고 로그 마지막 줄에 사유가 남았습니다. `erase_timeout` 은 시연용 가짜 브리지의 문자열이고, 실제 브리지는 `erase` 로 보고합니다.*

![배포 작업 상태](images/diagrams/job-lifecycle.png)

*작업은 대기 → 실행 중 → 완료·실패·취소 로 끝납니다.*

| 작업 상태 | 뜻 |
|---|---|
| 대기 | 예약 시각을 기다리거나 앞 작업이 끝나기를 기다림 |
| 실행 중 | 호기를 한 대씩 진행 중 |
| 완료 | 모든 호기 성공 |
| 실패 | 한 대 이상 실패, 또는 실행 중 서버가 재시작됨 |
| 취소 | 사용자가 취소, 또는 서버가 꺼져 있다 예약 시각이 30분 넘게 지남 |

| 호기 메시지 | 조치 |
|---|---|
| `호기 오프라인 (heartbeat 없음)` | 호기 전원·Wi-Fi 를 확인하고 다시 작업 |
| `브리지 펌웨어가 메인보드 OTA 를 지원하지 않음 (… 0.5.0 이상 필요)` | 브리지부터 0.5.x 로 올림 (0.5.0 미만은 USB) |
| `브리지에 dspfw 파티션이 없음 …` | 그 브리지를 USB 로 전체 굽기 |
| `브리지 보고 실패: <코드>` | 코드별 조치는 [10-5](#10-5-메인보드-ota-실패) |
| `브리지 보고 없음 (…초, '…' 대기 중)` | 브리지의 보고 패킷 1개가 유실됐을 수 있음. **호기 현황** 에서 메인보드 버전이 이미 새 것이면 성공한 것. 아니면 다시 작업 |
| `브리지 OTA 실패: <사유>` | [10-4](#10-4-브리지-ota-실패) |
| `앞 호기 실패로 중단` (건너뜀) | 원인을 고친 뒤 남은 호기로 새 작업 |
| `서버 재시작` | 서버가 실행 중에 꺼졌음. 새 작업으로 다시 |
| `취소` | 사용자가 취소 |

- 실패한 작업을 다시 돌리는 단추는 없습니다. **새 작업** 을 만듭니다. **업데이트 필요한 호기 선택** 을 쓰면 남은 호기만 고를 수 있습니다.
- 실행 중 **취소** 를 누르면 진행 중인 호기는 실패로, 남은 호기는 건너뜀으로 기록됩니다.
  서버는 기다리기만 멈춥니다. 이미 브리지에 보낸 메인보드 적용은 브리지가 끝까지 진행하므로, 결과는 **호기 현황** 의 메인보드 버전으로 확인합니다.
- 작업 기록은 **삭제** 로 지웁니다. 실행 중인 작업은 지울 수 없습니다.

### 6-5. 예약

- 예약 시각이 되면 실행 중인 작업이 없을 때 시작합니다.
- 서버가 꺼져 있다가 예약 시각이 **30분 넘게** 지나서 켜지면 그 작업은 자동 취소됩니다. 야간 예약이 아침에 갑자기 도는 것을 막기 위해서입니다. 다시 예약합니다.
- 메뉴에 `배포 작업 (1 예약)` 처럼 예약 건수가 보입니다.
- 오프라인 호기는 실행 시각에도 heartbeat 가 없으면 실패합니다.
- 서버가 켜져 있는 동안 **앞 작업이 길어져 밀린 예약** 은 30분이 넘어도 취소되지 않고 앞 작업이 끝나면 바로 시작합니다. 목록에는 `(곧)` 으로 보입니다. 생산 시간에 걸칠 것 같으면 직접 취소합니다.
- PC 재부팅 직후 예약 시각이 되면 heartbeat 를 받기 전에 시작해 '호기 오프라인' 으로 실패할 수 있습니다. Windows 자동 재부팅 시각을 예약 시각과 떨어뜨려 둡니다.

## 7. 설정 appsettings.json

설치 폴더의 `appsettings.json` 을 고칩니다. 지금 적용된 값은 **설정** 화면에서 봅니다.

### 7-1. 고치는 순서

1. 메모장을 **관리자 권한으로 실행** 하고 `C:\AgvFotaGateway\appsettings.json` 을 엽니다.
2. 값을 고치고 저장합니다. JSON 문법(쉼표, 따옴표)을 지킵니다. 경로의 `\` 는 `\\` 로 씁니다.
3. 서비스를 재시작합니다. 아래 둘 중 하나.
   - `services.msc` → **AGV FOTA Gateway** → **다시 시작**
   - 관리자 명령 프롬프트:
     ```bat
     net stop AgvFotaGateway
     net start AgvFotaGateway
     ```
4. **설정** 화면에서 바뀐 값을 확인합니다.

- JSON 문법이 틀리면 서비스가 시작되지 않습니다. [10장](#10-문제-해결)을 봅니다.
- 서버 업데이트는 `appsettings.json` 을 덮어쓰지 않습니다. 새 버전에서 생긴 키는 파일에 없어도 코드 기본값으로 동작합니다.
- 아래 표의 값은 zip 에 든 `appsettings.json` 값이고, 코드 기본값과 같습니다. `Urls` 만은 지우면 안 됩니다.

### 7-2. 서버·브리지 (`Urls`, `Gateway`)

| 키 | 기본값 | 설명 |
|---|---|---|
| `Urls` | `http://0.0.0.0:8080` | 웹 주소와 포트. 지우지 않습니다 |
| `Gateway.UdpPort` | `50000` | 브리지 수신 UDP 포트. 브리지 `server_port` 와 같아야 함 |
| `Gateway.RfidPort` | `50001` | RFID 로그 수신 포트. `0` = 받지 않음 |
| `Gateway.DataDir` | `data` | 데이터 폴더. 상대 경로면 설치 폴더 기준. 절대 경로도 됨 |
| `Gateway.OfflineAfterSec` | `5` | heartbeat 가 이 초 넘게 없으면 오프라인 |

## 8. 데이터와 백업

### 8-1. 폴더 구성

```text
C:\AgvFotaGateway\
├─ AgvFotaGateway.exe          서버
├─ AgvFotaGateway.exe.old      서버 업데이트 뒤 남는 이전 버전 (되돌리기용)
├─ appsettings.json            설정
├─ start.bat · install-service.bat · uninstall-service.bat
└─ data\
   ├─ gateway.db               데이터베이스 (SQLite)
   ├─ gateway.db-wal, -shm     데이터베이스 보조 파일 (함께 다룸)
   ├─ firmware\<id>\<파일>      올린 펌웨어 파일
   ├─ logs\gateway-YYYYMMDD.log 서버 로그 (14일 보관)
   └─ update\                  서버 업데이트 작업 폴더 (apply.log 등)
```

`gateway.db` 에 들어 있는 것:

| 표 | 내용 |
|---|---|
| `firmware` | 펌웨어 목록 (파일 자체는 `data\firmware\`) |
| `jobs`, `job_targets` | 배포 작업, 호기별 결과·로그 |
| `agv_groups` | 호기 소속(구역) |
| `agv_positions` | 호기별 최근 위치 |
| `agv_last_seen` | 호기별 마지막 접속·상태 (30초에 한 번, 버전이 바뀌면 바로 기록) |
| `meta` | 스키마 버전 |

### 8-2. 백업

| 방법 | 범위 | 서비스 |
|---|---|---|
| **설정** 화면 → **백업 내려받기** | DB 만 | 실행 중에도 됨 |
| 브라우저로 `http://<PC IP>:8080/api/db/backup` | DB 만 (`gateway-YYYYMMDD-HHmm.db`) | 실행 중에도 됨 |
| `data\` 폴더 통째 복사 | DB + 펌웨어 파일 + 로그 | **멈춘 뒤** 복사 |

- DB 백업에는 펌웨어 파일이 들어가지 않습니다. 펌웨어까지 지키려면 `data\firmware\` 도 따로 복사합니다.
- 서비스를 멈추지 않고 파일을 복사하지 않습니다. `gateway.db`·`-wal`·`-shm` 이 서로 맞지 않을 수 있습니다.
- DB 파일을 보려면 [DB Browser for SQLite](https://sqlitebrowser.org/) 의 **Open Database Read Only** 로 열거나, 백업으로 받은 사본을 엽니다. 실행 중인 `gateway.db` 를 쓰기 모드로 열어 두면 서버가 DB 를 기다리느라 **브리지 통신 전체가 멈출 수 있습니다**.

### 8-3. 복원

1. 서비스를 멈춥니다 (`net stop AgvFotaGateway`).
2. `data\gateway.db`, `gateway.db-wal`, `gateway.db-shm` 을 다른 폴더로 옮깁니다.
3. 백업 파일을 `data\gateway.db` 이름으로 복사합니다.
4. 필요하면 `data\firmware\` 도 백업본으로 되돌립니다.
5. 서비스를 시작합니다 (`net start AgvFotaGateway`).

### 8-4. 옛 JSON 파일 자동 이전

SQLite 이전 버전의 파일이 있으면 첫 실행 때 DB 로 옮깁니다. 옮긴 파일은 이름 뒤에 `.migrated` 가 붙습니다.

| 옛 파일 | 옮겨 가는 표 |
|---|---|
| `data\jobs.json` | `jobs`, `job_targets` |
| `data\firmware\index.json` | `firmware` |
| `data\agv_groups.json` | `agv_groups` |

- DB 스키마는 서버가 시작할 때 자동으로 맞춥니다. 기존 열은 지우지 않습니다.

## 9. 서버 업데이트

설치된 서버는 새 정식 릴리스를 스스로 확인하고 받습니다. 적용은 화면에서 누릅니다.

*매니페스트로 새 버전을 알고, zip 을 받아 SHA-256 을 확인한 뒤, 배치 파일이 서비스를 멈추고 파일을 바꿔 다시 켭니다.*

*시연 환경(로컬 빌드, `Update.Enabled=false`)이라 받기·적용 단추가 꺼져 있습니다. 정식 설치본에서는 새 버전이 있으면 켜집니다.*

### 9-1. 화면에서 업데이트

1. 메뉴 **서버 업데이트** 옆에 ● 가 붙으면 새 버전이 있습니다.
2. **지금 확인** 으로 바로 확인할 수도 있습니다.
3. **받기** 를 누릅니다. `.partial` 로 받고 SHA-256 이 맞을 때만 채택합니다.
4. 받으면 화면 위에 "새 서버 버전 … 을(를) 받았습니다" 띠가 뜹니다.
5. 배포 작업이 없는 때 **적용 (서비스 재시작)** 을 누릅니다.
6. 약 10초 뒤 화면이 다시 붙습니다. **기록** 에 `업데이트 vX.Y.Z 적용됨` 이 보이면 끝입니다.

> **알려진 문제 — 서비스로 설치한 경우** ([점검 I-01](REVIEW_2026-10-10.md#4-1-서버-업데이트-뒤-서비스로-재시작-안-됨-i-01-높음))

> 적용한 뒤 `services.msc` 에서 **AgvFotaGateway** 가 **중지됨** 이면, 관리자 명령 프롬프트에서 다음을 실행합니다.
>
> ```bat
> taskkill /f /im AgvFotaGateway.exe
> sc start AgvFotaGateway
> ```
>
> 고치기 전까지는 [9-4 수동 업데이트](#9-4-수동-업데이트) 를 권장합니다.

- 자동 확인: 시작 3초 뒤 한 번, 이후 6시간마다.

- 배포 작업이 실행 중이면 적용하지 않습니다.
- `appsettings.json` 과 `data\` 는 그대로 둡니다.
- 이전 exe 는 `AgvFotaGateway.exe.old` 로 남습니다. **이전 버전(…)으로 되돌리기** 로 한 세대 되돌립니다.
- **브라우저로 받기 (항상 최신)** 링크로 zip 을 직접 받을 수 있습니다.

| 화면의 빌드 종류 | 어디서 온 것 | 자동 업데이트 |

| 로컬 빌드 | 직접 빌드 | 확인·받기만. 교체하지 않음 |

### 9-2. 저장소 공개 여부와 사내 서버

|---|---|---|
| 저장소 **공개** | 기본값 그대로 | 사내망에서도 `github.com` 만 열려 있으면 됨. 단 GitHub 는 릴리스 파일을 `*.githubusercontent.com` 으로 넘겨 내려보내므로 그 주소도 막히지 않아야 함 (확인 필요) |
| 저장소 **비공개** | 기본값 | 매니페스트 주소가 404 → "정식 릴리스가 없거나 접근할 수 없음". 공개로 바꾸거나 아래 사내 서버 방식 |
| 비공개 + 사외망 | `GitHubToken` 에 토큰 (Contents: Read) | api.github.com 폴백으로 확인. 사내망에서 api.github.com 이 막히면 안 됨 |
| 사내 웹·파일 서버로만 배포 | `BaseUrl` 을 사내 주소로 | 아래 구조로 릴리스 자산 3개를 복사 |

사내 서버 폴더 구조 (`BaseUrl` 아래):

```text
releases/latest/download/AgvFotaGateway.json
releases/download/vX.Y.Z/AgvFotaGateway_win-x64.zip
releases/download/vX.Y.Z/AgvFotaGateway_win-x64.zip.sha256
```

- 구조를 맞추기 어려우면 `ManifestUrl` 에 매니페스트 주소를 직접 주고, 매니페스트의 `url` 에 zip 절대 주소를 넣습니다.
- 공유 폴더도 됩니다: `"BaseUrl": "file://server/share/fota"`. 서비스 계정(LocalSystem)이 그 공유를 읽을 수 있어야 합니다 (확인 필요).

### 9-3. 적용 기록

- 교체 과정: `data\update\apply.log` (배치 파일이 남김)
- 확인·받기·적용 메시지: 화면 **기록** (최근 100줄), 서버 로그 `data\logs\` 의 `update:` 줄

### 9-4. 수동 업데이트

자동 적용이 실패했거나 인터넷이 없을 때.

1. 새 zip 을 받습니다.
2. 배포 작업이 실행 중이 아닌지 확인합니다.
3. 관리자 명령 프롬프트에서 서비스를 멈춥니다.
   ```bat
   net stop AgvFotaGateway
   ```
4. 설치 폴더의 `AgvFotaGateway.exe` 를 `AgvFotaGateway.exe.old` 로 이름을 바꿉니다 (되돌리기용).
5. zip 안 `AgvFotaGateway\` 폴더의 파일을 설치 폴더로 복사합니다. **`appsettings.json` 은 복사하지 않습니다.** `data\` 는 zip 에 없습니다.
6. 서비스를 시작합니다. `install-service.bat` 을 다시 실행해도 됩니다.
   ```bat
   net start AgvFotaGateway
   ```
7. **설정** 화면에서 버전을 확인합니다.

### 9-5. 수동 되돌리기

1. `net stop AgvFotaGateway`
2. `AgvFotaGateway.exe` 를 다른 이름으로 바꿉니다 (예: `AgvFotaGateway.exe.bad`).
3. `AgvFotaGateway.exe.old` 를 `AgvFotaGateway.exe` 로 바꿉니다.
4. `net start AgvFotaGateway`

| 설정을 바꿨는데 그대로 | 서비스를 재시작했는지. **설정** 화면 맨 위에 나온 `appsettings.json` 경로가 고친 파일인지 |

### 10-3. 호기

![호기가 안 보일 때](images/diagrams/troubleshoot-agv-missing.png)

*위에서부터 차례로 확인합니다. 브리지 콘솔 `stat` 은 USB 콘솔이나 BLE 앱에서 칩니다.*

| 증상 | 확인 · 조치 |
|---|---|
| 호기가 아예 안 보임 | 위 그림 순서. 브리지 `server` = 이 PC IP, 방화벽 UDP 50000, 브리지 `stat` 의 `tx_err` |
| `N초 전` (오프라인) | heartbeat 가 5초 넘게 없음. 호기 전원, Wi-Fi(RSSI), AP |
| `ota` 가 `pending` | **PING**. 브리지 배포 작업은 시작할 때 자동으로 확정 후 진행 |
| `cfg` 가 `trial` | 원격 설정 확정 대기. 180초 안에 **PING**. 지나면 이전 설정으로 복구됨 |
| 메인보드 열 `-` | 브리지 0.5.0 미만. 브리지부터 올림 |
| 메인보드 `?` | 앱이 버전 응답을 안 함. 앱에 `dsp/app` 지원 코드가 있는지, 첫 `.dspfw` 를 아직 적용 안 했는지(앱 헤더가 비면 부트로더가 대기), J4 배선 |
| `⚠ 파티션 없음` | USB 전체 굽기 |
| `손실` 이 계속 늘어남 | 무선 품질. RSSI·AP 위치 |

### 10-4. 브리지 OTA 실패

배포 작업 메시지 기준입니다.

| 메시지 | 원인 · 조치 |
|---|---|
| `브리지 OTA 실패: begin …` | 브리지가 서버 8080 에 접속하지 못함. 방화벽, `PublicBaseUrl`(NIC 여러 개) |
| `브리지 OTA 실패: perform …` / `finish …` | 받는 중 끊김 또는 이미지 검증 실패. 무선 품질 확인 후 다시 |
| `브리지 OTA 실패: project mismatch …` | 다른 프로젝트 이미지 |
| `브리지가 이미 OTA 진행 중` | 잠시 뒤 다시 |
| `OTA_RESULT 없음 (3분)` | 브리지 응답 없음. 통신 로그 확인 |
| `재부팅 후 heartbeat 없음 (90초) — 180초 뒤 이전 펌웨어로 롤백됨` | 새 펌웨어가 서버에 붙지 못함. 몇 분 뒤 호기 현황에서 버전 확인 |
| `확정(valid) 안 됨` | 새 펌웨어로 재부팅했지만 서버가 보낸 확정 PING 1개가 닿지 않음. **180초 안에** **호기 현황 → 그 호기 행 → PING** 을 누르면 새 버전으로 확정됩니다. 180초가 지났거나 그 사이 재부팅하면 이전 펌웨어로 롤백되므로 작업을 다시 실행 |
| `브리지가 이전 업데이트를 확정하지 못함 (ota=pending 유지)` | 작업 시작 때 PING 을 반복해도 확정되지 않음(서버 패킷이 브리지에 닿지 않음). 브리지를 재부팅하면 이전 펌웨어로 돌아가므로 그 뒤 다시 실행 |
| `버전 불일치: 기대 …, 실제 …` | 롤백됐거나 다른 이미지 |
| `서버 IP 를 알 수 없음 — PublicBaseUrl 설정` | `Gateway.PublicBaseUrl` 을 정함 |

### 10-5. 메인보드 OTA 실패

![메인보드 OTA 단계별 실패 코드](images/diagrams/mainboard-ota-errors.png)

*로그의 마지막 단계와 코드로 어디서 멈췄는지 봅니다. 지우기(erase) 뒤에 실패하면 메인보드 앱이 없는 상태가 됩니다.*

작업 메시지는 `브리지 보고 실패: <코드>` 형식입니다.

| 코드 | 원인 | 조치 |
|---|---|---|
| (서버) `지원하지 않음 … 0.5.0 이상 필요` | 브리지 펌웨어가 낮음 | 브리지부터 올림 (0.5.0 미만은 USB) |
| `no_partition` / (서버) `dspfw 파티션이 없음` | 구 파티션 브리지 | USB 전체 굽기 |
| `http_init` · `http_open` · `http_status` · `http_length` · `http_read` · `http_short` · `http_overrun` | 브리지가 서버 8080 에서 파일을 못 받음 | 방화벽, `PublicBaseUrl` |
| `image_crc` · `crc_mismatch` | 받은 파일 손상 | 다시 실행. 반복되면 파일을 다시 올림 |
| `flash_erase` · `flash_write` · `stage_invalid` | 브리지 저장 영역 오류 (`stage_invalid` 는 지우기 전이라 앱은 그대로) | 다시 실행. 반복되면 브리지 점검 |
| `app_ng_01` / `02` / `03` / `04` / `09` | 메인보드 앱이 거부: 주행 중 / 충전 중 / 전압 부족 / 에러 상태 / 기타 | AGV 정지·충전 해제 후 다시 |
| `no_bootloader` | 부트로더 응답 없음 | 부트로더 설치 여부([dsp/README.md](https://github.com/Leepy0/AGV_Wifi_Bridge/blob/main/dsp/README.md)), 메인보드 전원, J4 배선 |
| `boot_proto` | 부트로더와 브리지의 프로토콜 버전이 다름 | 부트로더·브리지 버전을 맞춤 |
| `uart_busy` · `busy` · `not_ready` · `esp_ota_busy` / (서버) `브리지가 이미 메인보드를 프로그래밍 중` | 브리지가 다른 일 중 | 잠시 뒤 다시 |
| `bad_request` | 브리지가 받은 명령의 `url` 이 잘못됨 | `PublicBaseUrl` 이 `http://` 로 시작하는지 |
| `erase` · `write` · `write_timeout` · `program` · `verify_block` · `stage_read` · `stage_block` · `write_header` · `verify` | 굽는 중 실패. **메인보드 앱이 지워진 상태**(버전 `?`) | 같은 펌웨어로 **새 작업** 을 바로 실행. 앱이 응답하지 않으면 브리지가 부트로더로 바로 굽습니다 |
| `app_no_reply` | 굽고 나서 앱이 응답 없음 | 앱의 `fwup_boot_ok()` 호출·링커 설정 확인. 이전 버전 `.dspfw` 로 다시 |
| `ver_mismatch` / (서버) `적용 후 앱 버전 … 이 이미지 … 과 다름` | 앱이 보고한 버전이 이미지와 다름 | 버전 문자열 8자 이하, 앱의 버전 정의 확인 |
| `not_staged` · `job_mismatch` | 받아 둔 이미지가 없거나 다른 작업 것 | 새 작업으로 다시 |
| (서버) `브리지 보고 없음 (N초, '…' 대기 중)` | 받기 3분, 적용 중 90초 동안 보고가 끊김 | 통신 로그, 호기 온라인 여부 |
| (서버) `heartbeat 의 메인보드 버전이 … 가 아님` | 완료 보고 뒤 30초 동안 heartbeat 버전이 안 바뀜 | 호기 현황에서 버전 확인 |

> 위 조치 중 "지운 뒤 다시 굽기" 복구는 벤치 시험 항목입니다. 실기에서는 아직 검증 전입니다.

## 11. 제거

1. `uninstall-service.bat` 을 우클릭 → **관리자 권한으로 실행** 합니다.
2. 서비스를 멈추고 지웁니다. 방화벽 규칙 두 개(`AGV FOTA Gateway HTTP`, `AGV FOTA Gateway Bridge UDP`)도 지웁니다.
3. `삭제했습니다.` 가 나오면 끝입니다.

- 설치 폴더와 `data\` 는 남습니다. 다시 `install-service.bat` 을 실행하면 이전 데이터 그대로 이어서 씁니다.
- 완전히 지우려면 `data\` 를 백업한 뒤 설치 폴더를 지웁니다.
- ACS 중계를 `Server` 모드로 쓰며 직접 추가한 방화벽 규칙은 따로 지웁니다.
